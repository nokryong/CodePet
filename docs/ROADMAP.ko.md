# CodePetMODnMOBILE 개발 로드맵

기준일: 2026-11-04 (Asia/Seoul) · 기준 브랜치: `develop`

## 1. 제품 목표와 합의 범위

공식 에이전트 앱에서 기대하는 첨부·도구·승인·미리보기 흐름을
CodePet PC판과 Android 앱에서 제공한다. 공식 앱의 모든 기능을 동일하게
사용할 수 있다고 전제하지 않고, 실제 CLI/공식 연동 인터페이스가 제공하는 기능부터 검증한다.

확정한 제품 방향:

- 원본 Fork를 유지하며 개조한다. 원본 업데이트를 계속 병합할 수 있게 한다.
- Windows PC를 첫 지원 대상으로 삼고, 기존 macOS/Linux 기능은 가능한 한 보존한다.
- 모바일은 설치형 **Android 앱(APK)**이다. PWA/iOS 앱은 초기 범위에 넣지 않는다.
- 에이전트와 실제 파일·브라우저 작업은 PC에서 실행한다. Android는 원격 클라이언트다.
- PC가 켜져 있고 연결되어 있어야 한다. PC 없이 동작하는 서버형 제품은 후속 별도 범위다.
- Claude는 기존 Chrome과 그 로그인 상태를 사용하도록 연결한다.
- Codex는 사용 중인 브라우저 연결 재사용을 우선 조사한다. 앱 전용 도구를 CLI에 복제할 수 있다고 가정하지 않는다.
- 에이전트별 모델·추론 수준을 대화 안에서 바꾸고 기본적으로 다음 턴부터 적용한다.
- PC·Android에서 사진/파일 첨부, 이미지/파일 출력, 문서/GUI 미리보기를 편하게 사용한다.
- 초기 공급자는 Claude Code·Codex다. 기존 AGY·Grok 통합을 제거하지 않는다.

## 2. 현재 소스에서 확인한 출발점

아래는 v1.2.2 소스 검사 결과다. 실제 계정으로 기능 테스트를 완료했다는 의미는 아니다.

| 영역 | 현재 구현 | 계획에서 필요한 보완 |
|---|---|---|
| 실행 | `src/chat/chat-agent-runner.js`의 CLI subprocess | 양방향 승인과 장기 세션을 지원하는 어댑터 |
| 권한 | `chat-argv.js`: Claude 읽기 모드는 `Read,Grep,Glob`만 제공 | 파일 쓰기 여부와 웹/브라우저/명령 도구 권한 분리 |
| MCP | Claude 실행에 `--strict-mcp-config` 사용 | 선택한 연결만 명시적으로 구성, 상태·오류 표시 |
| 승인 | `chat-room.js`: 일부 실패를 승인으로 판정하고 실행 재시도 | 특정 도구 호출에서 정지·승인·재개, 중복 부작용 방지 |
| 모델/추론 | `src/chat.js` 선택 UI, CLI 실행 플래그 이미 존재 | 적용 시점, 실제 적용 값, 모델 변경 후 대화 연속성 검증 |
| 세션 | `chat-ipc.js` 세션 scope에 모델·추론 포함 | 모델/추론 변경과 세션 정체성을 분리, 이전 기록 마이그레이션 |
| 첨부 | +, 드롭, 클립보드 이미지, 파일 20MiB/세션 200MiB | 전송 상태, 실패 복구, 썸네일, 원격 첨부와 접근 제어 |
| 파일 이해 | 공급자별 이미지/경로/텍스트 전달 방식 다름 | 파일 종류별 지원/변환/미지원 명시 |
| 기록 | JSONL·검색·내보내기·전용 CLI 기록과 writer 보호 | 공통 이벤트 재생, Android 재연결, 호환 마이그레이션 |
| 계정 설정 | 사용자 홈·환경 변수·계정별 격리 저장소가 함께 존재 | 실제 config 경로 진단, 환경 상속과 계정 분리 일치 |
| 업데이트 | 원본 릴리스 저장소와 다운로드 검증 경로 고정 | 개조판 릴리스 채널·서명/체크섬·업데이트 검증 |
| CI/릴리스 | Node 테스트, 3개 OS 빌드; main 푸시와 v* 태그에 릴리스 | 계획 게시와 실제 배포 분리, Android CI/서명키 관리 |

## 3. 개발 단계와 완료 기준

달력상 기간보다 아래 완료 기준을 우선한다. 기능을 한꺼번에 재작성하지 않는다.

| 단계 | 결과물 | 진입 조건 | 완료 기준 |
|---|---|---|---|
| P0 기반 정리 | 원본 기준선, 문서, 재현 사례 | Fork 확보 | 기존 테스트/빌드 결과 기록, 오류 재현과 자료 분리 |
| P1 기술 검증 | 공급자·승인·브라우저 실행 가능성 보고 | P0 | 아래 검증 항목별 성공/실패·대안·인증 경로가 기록됨 |
| P2 공통 실행부 | 세션/이벤트/파일/승인의 공통 계약 | P1의 핵심 경로 선택 | PC에서 두 공급자 호출, 저장·재연결·취소·오류 재생 검증 |
| P3 PC 작업 MVP | 권한·세션·모델·브라우저 | P2 | 실제 PC 작업 시나리오가 계정별로 통과 |
| P4 첨부·결과물 UX | 파일/이미지/문서/GUI 미리보기 | P3, P2 파일 계약 | PC에서 입력→처리→미리보기→재첨부 흐름 통과 |
| P5 Android MVP | 설치 가능한 APK와 PC 연결 | P2 안정화, P3 핵심 기능 | 실기기에서 같은 대화·첨부·승인·중단·모델 변경 통과 |
| P6 연결·운영 완성 | 외부 연결, 알림, 복구, 다중 에이전트 | P4/P5 | 절전/재시작/중복 승인/동시 수정 시나리오 통과 |
| P7 배포·원본 병합 | 개조판 PC/APK 릴리스와 업데이트 | 각 릴리스 범위 검증 | 설치·업그레이드·백업·원본 병합 리허설 통과 |

P2의 계약이 안정화되면 Android 화면 개발을 진행할 수 있지만,
P3에서 검증되지 않은 에이전트 기능을 모바일에서 완료로 표시하지 않는다.

### P0. 개발 기반과 회귀 기준선

- [ ] 원본 커밋, Fork 원격, 개발 브랜치, 버전·라이선스·자산 출처 기록.
- [ ] 해당 Node 버전에서 의존성 설치, 기존 `npm test`, Windows 실행/빌드 결과 기록.
- [ ] 현재 실패를 재현: 웹검색 승인, Claude config 경로, 모델 변경, 첨부 전달.
- [ ] 테스트용 가상 대화·이미지·문서 준비. 실제 자격 증명과 기록은 저장소 밖에 둔다.
- [ ] 릴리스 워크플로가 원본/개조판을 혼동하지 않도록 변경안을 문서화.

완료 증거: 실행 명령·버전·테스트 결과·재현 절차가 진행 문서 또는 링크된 PR에 존재.
현재 계획 문서 게시만으로 P0 전체를 완료 처리하지 않는다.

### P1. 먼저 풀어야 할 기술 검증

- [ ] **Claude**: 현재 로그인 경로를 감지하고 기존 구독/인증으로 CLI 연동이 가능한지 확인.
- [ ] CLI 양방향 프로토콜과 공식 SDK의 승인/세션 기능을 비교한다. SDK 선택 시 인증·과금·배포 조건을 별도 확인하고 기존 구독에서 API 과금으로 묵시적으로 전환하지 않는다.
- [ ] **Codex**: App Server에서 인증, 모델 목록, 턴 스트리밍, 도구 승인, 세션 재개, 모델·추론 변경을 검증.
- [ ] **Claude Chrome**: 기존 Chrome, 공식 확장, native messaging, 사이트 승인, 비대화형 실행 시의 연결을 Windows에서 검증.
- [ ] **Codex 브라우저**: 현재 도구가 앱 전용인지 재사용 가능한 MCP인지 분류. 재사용 불가 시 대안을 비교하되 사용자의 기존 브라우저 선호를 임의로 바꾸지 않는다.
- [ ] 계정·CLI config·작업 디렉터리·명령 wrapper가 브라우저와 스킬 탐지를 방해하는지 확인.
- [ ] 모델 변경 전후 CLI 세션 ID와 대화 맥락 유지 여부를 검증. 미지원 모델/추론은 선택 불가로 표시.

완료 증거: 각 항목의 실제 결과, 최소 재현, 사용한 인터페이스/버전, 미해결점이 기록된 기술 결정.
막히는 경로가 있으면 완전한 공식 앱 동등성을 약속하지 않고 대안과 영향부터 제시한다.

### P2. PC와 Android가 공유하는 실행부

- [ ] Electron IPC에서 실행/세션/도구 처리를 점진적으로 분리. 기존 UI가 먼저 같은 서비스를 사용.
- [ ] 공급자 어댑터: capabilities, 계정/config 진단, 세션, 턴, 도구 이벤트, 승인, 취소.
- [ ] 공통 계약: 대화·참가자·실행·도구 호출·파일·승인·모델 설정과 오류.
- [ ] 이벤트 순번/ID·커서 기반 재연결·누락 복구·중복 요청 방지·다중 화면 반영.
- [ ] 파일 ID 기반 저장/전송/미리보기. 실행 파일 접근이나 임의 PC 경로 공개를 방지.
- [ ] 버전 있는 저장 형식과 기존 JSONL/전용 CLI 세션의 백업·마이그레이션.
- [ ] 서버 기능은 기본적으로 로컬에서 시작. 원격 연결은 페어링 단계까지 외부 공개하지 않음.

완료 증거: fake provider 계약 테스트와 실제 공급자 테스트를 구분하고,
PC에서 동일한 서비스로 대화·승인·파일·재연결 흐름이 동작한다.

### P3. PC에서 막힘 없이 작업하기

- [ ] 워크스페이스별 읽기/쓰기와 웹검색/웹읽기/명령/MCP/브라우저 권한을 독립 설정.
- [ ] 이번 한 번/현재 세션/작업공간 규칙으로 승인. 실제 backend가 강제하는 범위와 UI 정책을 구분.
- [ ] 승인 카드에 도구·대상·입력·변경 영향·유효 시간을 표시. 거부·만료·취소를 재개 프로토콜에 반영.
- [ ] 브라우저 연결/해제·프로필 선택·상태 진단·사이트 승인. Claude와 Codex의 지원 범위를 구분.
- [ ] 같은 대화에서 모델/추론 변경, 현재 턴·다음 턴 설정 구분, 메시지별 실제 사용 모델 표시.
- [ ] CLI 스킬·MCP·플러그인 목록과 활성 상태/누락 이유 표시. 초기 설치 관리는 공식 도구를 활용.
- [ ] 도구 실행 카드, 검색 출처, 승인 대기, 오류 원인, 중지와 후속 지시.
- [ ] 실행 중 추가 지시 지원 여부를 공급자별로 표시. 미지원이면 다음 턴 대기로 처리.

완료 시나리오: 파일은 읽기만 허용한 대화에서 웹검색 → 기존 브라우저 작업 승인 →
결과 확인 → 모델·추론 변경 → 이전 내용을 참조한 후속 질문.
파일 편집/명령은 설정 범위를 지키고, 승인 거부가 전체 권한 우회로 바뀌지 않아야 한다.

### P4. PC의 첨부와 풍부한 결과 표시

- [ ] 여러 파일 선택·드롭·Ctrl+V 이미지·영역 캡처·썸네일·삭제·전송 상태·오류 복구.
- [ ] `@파일`/폴더 참조, 전송할 내용 확인, 초안과 첨부 유지.
- [ ] 용량 한도와 지원 형식을 UI에 표시. 기존 20MiB/200MiB를 근거 없이 무제한으로 바꾸지 않음.
- [ ] 공급자·모델·권한별 파일 지원 표. PDF/문서 변환·OCR 등은 실제 처리 도구를 확인한 뒤 제공.
- [ ] 출력 이미지를 확대·저장·다시 첨부. 이미지 생성/편집은 별도 도구 연결이 있을 때만 활성화.
- [ ] 생성 파일 카드·다운로드·폴더 열기·본문 미리보기·안전한 파일 링크.
- [ ] Markdown·표·코드·수식, PDF·문서·시트 미리보기. 원본 파일 다운로드를 함께 제공.
- [ ] HTML/차트/간단한 GUI 결과를 격리된 패널에서 표시. 권한 있는 앱과 분리된 실행 환경 사용.
- [ ] 코드 diff·적용 범위·되돌리기·체크포인트. 실행 중인 명령의 외부 부작용까지 되돌릴 수 있다고 표현하지 않음.

완료 시나리오: 캡처+문서 첨부 → 처리 여부 확인 → 이미지/파일/HTML 결과 확인 →
저장/재첨부 → 수정 요청. 잘못된 HTML·SVG·경로는 앱/PC 권한으로 실행되지 않는다.

### P5. Android 앱 MVP

- [ ] Kotlin + Jetpack Compose 기반 Android 전용 화면과 디버그 APK. 세부 버전/최소 OS는 P1에서 결정 기록.
- [ ] PC 기기 연결·해제·인증·만료·권한 범위·연결 상태. 같은 네트워크 연결부터 검증.
- [ ] 대화 목록·실시간 응답·참가자·모델/추론 선택·도구 카드·승인·중단.
- [ ] 사진 선택기, 파일 선택기, 카메라, 다른 앱의 공유 받기. 실제 MIME/크기/읽기 권한 검증.
- [ ] 업로드 진행·중단/재시도·중복 방지, 이미지 확대·파일 저장·외부 앱으로 열기.
- [ ] PC와 같은 파일 ID·메시지 ID·승인 ID 사용. 로컬 PC 절대 경로로 결과를 표시하지 않음.
- [ ] 화면 회전·앱 재실행·일시적 네트워크 끊김에 초안과 실행 상태 복구.
- [ ] 설치/실행/페어링/첨부/승인/결과 저장을 실제 Android 기기에서 검증.

완료 시나리오: 휴대폰에서 사진 공유 → PC Claude/Codex에 요청 → 휴대폰 승인 →
PC에서 실행 → 양쪽에 같은 결과 → 휴대폰에서 모델 변경 후 이어서 대화.

### P6. 원격 연결·알림·일상 사용 완성

- [ ] 집 밖 연결 방식 선택: 사설 VPN 우선 검증, 중계 서비스는 필요성과 운영 비용을 따로 결정.
- [ ] 기기 인증 폐기, TLS/신뢰 확인, 재연결, 메시지·승인 중복 방지.
- [ ] 완료/실패/승인 요청 알림. Android 백그라운드 제약에 맞춰 푸시/중계 필요성을 검증.
- [ ] 포그라운드 연결 알림과 앱 종료 상태의 푸시를 구분. 상시 WebSocket만으로 모든 알림을 보장하지 않음.
- [ ] PC 절전/오프라인/프로세스 종료 상태를 명확히 표시. 재연결 시 자동으로 작업을 중복 시작하지 않음.
- [ ] 대화 분기, 검색, 내보내기, 사용량·컨텍스트 표시, 접근성·한글 입력·키보드/터치 개선.
- [ ] 에이전트 간 작업 인계와 같은 파일 동시 수정 감지. 계정/세션/승인 경계를 유지.
- [ ] 알림 본문과 로그에 민감 정보가 노출되지 않도록 표시/보관 정책 제공.

### P7. 배포와 지속 유지

- [ ] 제품 이름·앱 ID·데이터 폴더·버전 체계·기존 데이터 이전 정책 결정.
- [ ] PC 업데이트 조회와 다운로드 검증 경로 모두 Fork 릴리스로 전환. 원본 EXE로 교체되지 않는지 검증.
- [ ] Windows 산출물, Android APK, 체크섬, 설치·업그레이드·복구 안내 제공.
- [ ] Android 서명키는 저장소 밖에서 관리. 업데이트 가능한 동일 서명 유지.
- [ ] CI에서 기존 공급자 회귀 + 공통 계약 + Android 빌드 + 필요한 UI 시나리오 수행.
- [ ] 처음에는 수동/검토된 릴리스. upstream의 main/v* 자동 릴리스 정책을 그대로 사용하지 않음.
- [ ] upstream 업데이트 병합 리허설과 변경 이력 기록. 개조 기능과 데이터 호환성 확인 후 릴리스.

## 4. 초기 범위에서 제외

- 공식 앱의 비공개 내부 도구/UI/브라우저를 그대로 재현하는 작업.
- PC가 꺼진 상태의 독립 실행, 호스팅형 다중 사용자 서비스, iOS/PWA, 앱스토어 출시 보장.
- 연결하지 않은 이미지/음성 생성 서비스, 모든 문서 형식의 완전 편집기.
- 자동 전체 권한 부여, 로그인 토큰/브라우저 쿠키를 휴대폰으로 복제하는 방식.

## 5. 일정과 진행 원칙

- 첫 구현 단위는 P0 기준선과 P1 기술 검증이다. 화면 전체 재작성이나 Android 전체 개발부터 시작하지 않는다.
- 각 단계는 실제 증거가 있는 항목만 체크한다. 모의 테스트/실기기/실공급자 검증을 구분한다.
- 새 요구는 해당 단계·완료 기준·선행 조건을 갱신한 뒤 작업한다.
- 진행 상황과 현재 막힌 점은 [STATUS.ko.md](STATUS.ko.md)에 기록한다.
